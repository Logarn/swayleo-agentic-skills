# Document Reconciliation

## Purpose and provenance

Recovered from internal/client copy comparisons and concurrent-edit preservation.

This workflow applies across brands by substituting the current brand's sources, account, scope and approval rules. It is a reusable instruction set, not evidence that a live system is configured.

## Inputs

Canonical document IDs and tabs, current revisions, comments, internal/client variants and explicit scope for edits.

If an input is unavailable, identify its effect and continue work that does not depend on it. Do not fill factual gaps with another brand's assumptions.

## Workflow

1. Identify each version's purpose and reviewer. Do not assume the newest edited file is approved or canonical.
2. Compare structure and text by campaign/section ID. Normalize whitespace only for comparison; retain the original content and formatting for edits.
3. Separate copy changes, offer/claim corrections, formatting differences and comment state. New subject lines in an internal draft remain proposals until approved.
4. Build a reconciliation plan stating which source wins for each difference and why. A later explicit client correction can supersede older calendar wording without approving unrelated internal copy.
5. Inspect comment anchors before changing headings or blocks. A detached comment remains a real comment; do not delete it or claim it is absent because it is not beside highlighted text.
6. Use guarded, scoped native edits. On a revision conflict, read the newer version and recompute the plan; never overwrite concurrent edits with a stale snapshot.
7. Read back changed sections, retained copy and comment identities. Render relevant pages for layout changes.
8. Report synchronized areas and unresolved differences. Do not silently publish internal strategy or private notes into client-facing documents.

## Deliverable

Difference register; source precedence decisions; planned/applied changes; preserved anchors; unresolved review items.

Use the output worksheet inside the downloadable library ZIP to structure a working draft. Adapt it to the requested deliverable; do not create extra files unless useful.

## Example

Internal copy has newer subjects, while the client's document has current offer corrections. Merge those as separate reviewable changes rather than replacing one whole document.

## Verification and completion

Canonical versions identified; authority documented; comments preserved; concurrency handled; supplied copy retained; client-facing scope respected.

Report what was completed, the source or saved record that proves it, and any unresolved blocker. Distinguish a draft, a saved change and a live action. Publishing, posting, scheduling or changing live systems requires the corresponding user request and available tools.
