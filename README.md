## Your agent. Our playbook.

The repeatable parts of agency work should get easier every time we do them.

This is a growing collection of Swayleo workflow skills: small, focused instructions that help an agent turn a brief into useful work. Start with a call transcript, a campaign idea or a messy client folder. Pick a skill. Give it the right context. Review what comes back.

**Nine skills to start. Built around work we actually need to do.**

## Give your agent the playbook

Copy this into your agent:

```text
Review https://github.com/Logarn/swayleo-agentic-skills.
Install all nine swayleo-*.md workflow skills into your supported skill
directory, each in its own named folder with SKILL.md as the entrypoint.
Preserve the YAML frontmatter. Do not overwrite existing skills.
Tell me which tools or account connections I need for my chosen task.
```

For Codex, the layout is:

```text
~/.codex/skills/
└── swayleo-call-to-tasks/
    └── SKILL.md
```

Repeat for the other skills. Other agents may use a different location or load the Markdown directly. Downloading the files alone does not guarantee automatic discovery.

## Put it to work

> **After a call:** “Use Call → Tasks on this transcript and these notes. Check existing tasks first. Flag missing owners.”

> **Before a campaign:** “Use Segmentation Strategy to audit these audiences, then help me build next month’s Campaign Calendar.”

> **Before an operations call:** “Use Operations Calls. Put decisions needed from leadership at the top. Keep it simple.”

## What you are installing

These are **new Swayleo workflow drafts**, based on our operations needs. They are ready to review and try on real tasks; they are not established SOPs or validated production automations.

Skills guide the work. Connected tools do the work. Monday.com, Slack, an ESP, Drive or Figma still need the appropriate tools, access and authorization. The sync skill designs or reviews a sync; it does not deploy one by being installed.

Some process choices remain open: naming conventions, calendar versus working days for +2 deadlines, sync ownership and whether the client-facing flow map becomes standard. The skills flag those choices instead of silently deciding them.

## Add more capability

Relevant plugin families available in the originating workspace:

| Need | Plugin family |
| :-- | :-- |
| Lifecycle messaging | Customer.io Journeys, Design Studio, Pipelines and SDK |
| Reporting and insights | Data Analytics: quality, KPIs, diagnostics and dashboards |
| Design and build | Figma design-to-code, diagrams and libraries |
| Shared operations docs | Google Drive, Docs, Sheets and Slides |
| Client deliverables | Documents, spreadsheets, presentations and PDF |
| Creative assets | Image generation |
| Agents and automation | Vercel AI SDK, workflows, backend and Chat SDK |

Install these separately from their official sources. Vendor plugin files are not bundled here. Customer.io support does not imply Klaviyo support, and a skill does not grant service access.

## Make it better

Find a repeated task. Write down the decisions that make the result good. Turn that into one focused skill. Try it on a real example, then improve it.

When contributing, include when the skill should run, the inputs it needs and the output it should produce. Keep client data, transcripts and credentials out of the repo.
