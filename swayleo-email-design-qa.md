# Email Design Qa

## Purpose and provenance

Expanded using recovered design QA and product/destination mismatch checks.

This workflow applies across brands by substituting the current brand's sources, account, scope and approval rules. It is a reusable instruction set, not evidence that a live system is configured.

## Inputs

Current approved copy; exact design frames or exports; brand assets; product variant reference; CTA destinations; intended mobile/desktop and email clients.

If an input is unavailable, identify its effect and continue work that does not depend on it. Do not fill factual gaps with another brand's assumptions.

## Workflow

1. Establish which design revision and copy revision are being reviewed. Inventory all in-scope campaigns, including plain-text variants; record missing frames.
2. For a brief, specify content hierarchy, image/product requirements, CTA priority, mobile behavior, live-text needs and alt-text guidance. Preserve the approved copy's job.
3. For QA, read actual rendered frames. Compare headings, body, disclaimers, offer mechanics and button labels against the approved copy, not an outdated internal draft.
4. Match product images to the exact SKU, size, pack, kit contents and use case. A similar-looking item is not interchangeable.
5. Check spacing, legibility, contrast, mobile order, button visibility, cropping and text embedded in images. Inspect plain-text designs too.
6. Test actual link destinations when accessible; a visual label does not prove the hyperlink. Keep untested build/client-render behavior separate from visible design findings.
7. Draft specific comments attached to the exact frame/node. Describe observed mismatch, expected change and source. Post comments only if requested.
8. Recheck fixes against the current revision. A design with no new visible issues still needs applicable approval, build and send checks.

## Deliverable

Campaign/frame | Finding | Evidence | Expected change | Owner/reviewer | Severity | Status. Add coverage: reviewed, missing, plain-text and unverified build behavior.

Use the output worksheet inside the downloadable library ZIP to structure a working draft. Adapt it to the requested deliverable; do not create extra files unless useful.

## Example

A kit brief specifies a stick, but the design shows a tin. Flag the image mismatch and verify the destination rather than rewriting unrelated copy.

## Verification and completion

All requested frames are accounted for; comments are actionable; actual links are distinguished from labels; visible QA is not presented as send approval.

Report what was completed, the source or saved record that proves it, and any unresolved blocker. Distinguish a draft, a saved change and a live action. Publishing, posting, scheduling or changing live systems requires the corresponding user request and available tools.
