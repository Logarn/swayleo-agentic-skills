# Operations Call

## Purpose and provenance

Expanded from the requested Monday and Wednesday operations-call process.

This workflow applies across brands by substituting the current brand's sources, account, scope and approval rules. It is a reusable instruction set, not evidence that a live system is configured.

## Inputs

Previous agenda and open actions; latest board state; relevant Slack decisions; current week/date; attendees and decision owners.

If an input is unavailable, identify its effect and continue work that does not depend on it. Do not fill factual gaps with another brand's assumptions.

## Workflow

1. Carry forward unresolved actions by stable ID, preserving owner and original due date. Close an action only with delivery or decision evidence.
2. Start with items that require a leadership decision, unblock work or carry a near-term deadline. State the decision needed and why it matters now.
3. Group remaining updates around project management, call-action capture, client folders, agent skills and academy only when there is something to discuss.
4. For each update separate what is built, what is proposed, what is blocked and what is needed next. Avoid narrating routine research.
5. Use a screenshot when it demonstrates a board structure, automation or mismatch more clearly than text. Caption what it shows and preserve a useful source link.
6. Capture decisions during the call, including scope and effective date. Convert agreed actions through call-to-tasks rather than silently changing every task.
7. Keep the same recurring document when requested; use dated sections and an open-action list. Do not create a separate document each time by default.

## Deliverable

Opening decisions: issue / decision needed / recommendation / owner. Then short operations bullets. End with Priority | Action | Owner | Due | Blocker | Source. Write in plain, informal language.

Use the output worksheet inside the downloadable library ZIP to structure a working draft. Adapt it to the requested deliverable; do not create extra files unless useful.

## Example

“Segmentation: choose the first two clients for an audience audit. Calendars are blocked because the current segment definitions are unclear.”

## Verification and completion

The top items require a real decision; old unresolved actions remain traceable; dates are current; completion and approval claims have evidence.

Report what was completed, the source or saved record that proves it, and any unresolved blocker. Distinguish a draft, a saved change and a live action. Publishing, posting, scheduling or changing live systems requires the corresponding user request and available tools.
