# Qa Comments

## Purpose and provenance

Recovered from saved cross-brand comment edits and comment-anchor verification.

This workflow applies across brands by substituting the current brand's sources, account, scope and approval rules. It is a reusable instruction set, not evidence that a live system is configured.

## Inputs

Exact document/frame and location, observed defect, supporting source, existing comment thread and requested action: draft, post, edit or resolve.

If an input is unavailable, identify its effect and continue work that does not depend on it. Do not fill factual gaps with another brand's assumptions.

## Workflow

1. Inspect the current content and existing comments. Confirm whether the finding is still present and whether a thread already covers it.
2. Write one concrete issue per comment: what is wrong and what needs to change. Add a source when the recipient needs it to verify the correction.
3. Use simple team language. Avoid long reports inside comments, vague questions and corporate phrasing.
4. When editing an existing comment, verify its author and stable ID, then edit in place within the authorized scope. Do not create a second comment to simulate an edit.
5. For Docs, confirm the correct tab and anchor; for Figma, use the exact current frame/node. If an anchor is detached, state that instead of claiming the comment disappeared.
6. Do not resolve a content-review thread because formatting was fixed. Resolve only the specific issue actually completed and only when requested.
7. Read back saved text and retain the native comment link. Drafting a Slack summary does not authorize sending it.

## Deliverable

Comment draft or verified edit: target/anchor | text | source | thread ID/link | saved/draft state. Keep the summary short.

Use the output worksheet inside the downloadable library ZIP to structure a working draft. Adapt it to the requested deliverable; do not create extra files unless useful.

## Example

“This claim and footnote do not match. Please use the approved claim with its matching footnote.”

## Verification and completion

Current evidence; specific correction; correct author/anchor; no duplicate thread; save state verified; no unintended body edit or send.

Report what was completed, the source or saved record that proves it, and any unresolved blocker. Distinguish a draft, a saved change and a live action. Publishing, posting, scheduling or changing live systems requires the corresponding user request and available tools.
