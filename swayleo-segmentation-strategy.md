# Segmentation Strategy

## Purpose and provenance

Expanded from the segmentation priority in the operations agenda.

This workflow applies across brands by substituting the current brand's sources, account, scope and approval rules. It is a reusable instruction set, not evidence that a live system is configured.

## Inputs

Brand objectives, ESP access or exports, actual segment logic, profile/event dictionary, consent fields, order data, campaign history and client priorities.

If an input is unavailable, identify its effect and continue work that does not depend on it. Do not fill factual gaps with another brand's assumptions.

## Workflow

1. Inventory actual definitions, not just segment names. Record source system, filters, exclusions, time windows, refresh behavior, count and date checked.
2. Verify the event/property semantics used. Distinguish subscriber status, purchase type, subscription product and marketing consent. Check missing values and identity behavior.
3. Map useful lifecycle states: prospect, first-time buyer, repeat buyer, subscription state where supported, replenishment and lapse. Define mutual exclusions only where required by the strategy.
4. Evaluate engagement with available signals and their limitations. Do not treat opens alone as proof of human activity or consent. Choose thresholds from the brand's cadence and data; label untested thresholds as hypotheses.
5. Inspect audience overlap, suppression and flow/campaign collisions. Preserve unsubscribed, bounced and other required exclusions using the platform's actual fields.
6. For each proposed segment state its business job, exact logical definition, data requirements, campaign use, expected size if measured, success metric and review trigger.
7. Prioritize by business need, usable data and ability to act. If the client priority is missing, prepare the audit framework and request the priority without inventing a leadership decision.
8. Keep a definition register and change log. Validate sample profiles at boundaries before activation; record the difference between planned and live definitions.

## Deliverable

Current definition register; gaps/overlaps; proposed segment specifications; priority backlog; measurement and review plan. Use ALL/ANY groups with explicit parentheses.

Use the output worksheet inside the downloadable library ZIP to structure a working draft. Adapt it to the requested deliverable; do not create extra files unless useful.

## Example

“Repeat buyers eligible for replenishment” needs order-count and product/window rules, consent and suppressions. A segment named VIP does not prove those conditions.

## Verification and completion

Definitions are reproducible; windows and exclusions are explicit; counts are dated; representative profiles match; proposed audiences are not claimed live.

Report what was completed, the source or saved record that proves it, and any unresolved blocker. Distinguish a draft, a saved change and a live action. Publishing, posting, scheduling or changing live systems requires the corresponding user request and available tools.
