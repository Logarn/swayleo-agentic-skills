# Campaign Design Qa

## Purpose and provenance

Recovered from past design reviews; complements the design-brief skill.

This workflow applies across brands by substituting the current brand's sources, account, scope and approval rules. It is a reusable instruction set, not evidence that a live system is configured.

## Inputs

Complete campaign list, current frame links, approved copy, product images, offer ledger and expected variants.

If an input is unavailable, identify its effect and continue work that does not depend on it. Do not fill factual gaps with another brand's assumptions.

## Workflow

1. Create a coverage register before reviewing: campaign ID, audience/version, frame/node and copy reference. Include plain-text campaigns and resends when in scope.
2. Read every current frame at a useful scale. Compare copy, product photo, pack/variant, CTA text, offer and disclaimers.
3. Record exact frame/node locations. A finding on a similar historical frame is not evidence of a defect in the current version.
4. Compare repeated claims/offers across the sequence for stale language. Distinguish a requested correction already fixed from one still present.
5. Group genuinely identical defects while naming every affected campaign. Avoid duplicate comments on the same issue and frame.
6. Write plain comments: observed problem, needed change and evidence. Avoid vague polish requests or unnecessary strategy rewrites.
7. Posting comments requires the user's requested scope. If only reviewing, deliver drafts; do not post or resolve existing threads.
8. Recheck fixes visibly. Keep review coverage and approval/build readiness separate.

## Deliverable

Coverage table and prioritized findings with exact anchors. A clean review means no new observed defects in the reviewed scope, not universal approval.

Use the output worksheet inside the downloadable library ZIP to structure a working draft. Adapt it to the requested deliverable; do not create extra files unless useful.

## Example

Three emails reuse the wrong product image: one grouped issue can name all three exact frames while retaining their separate review states.

## Verification and completion

All requested designs accounted for; current frames reviewed; duplicate findings removed; anchors precise; untested links/client renders stated.

Report what was completed, the source or saved record that proves it, and any unresolved blocker. Distinguish a draft, a saved change and a live action. Publishing, posting, scheduling or changing live systems requires the corresponding user request and available tools.
