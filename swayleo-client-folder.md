# Client Folder

## Purpose and provenance

Expanded from the four-document agenda and recovered template-migration work.

This workflow applies across brands by substituting the current brand's sources, account, scope and approval rules. It is a reusable instruction set, not evidence that a live system is configured.

## Inputs

Client folder, current document links, agreed templates, owner map, naming policy and any client-specific document requirements.

If an input is unavailable, identify its effect and continue work that does not depend on it. Do not fill factual gaps with another brand's assumptions.

## Workflow

1. Inventory intake, copy doc, flow doc and campaign calendar. Record canonical link, purpose, owner, status and missing content.
2. Treat the shorter client-facing flow map as optional until confirmed. Its purpose is a high-level build/strategy view; it does not replace execution detail silently.
3. Confirm the template is ready for cloning. An old export, visually plausible master or partly finished template is not proof of readiness.
4. When authorized to create from templates, copy natively to preserve tabs, tables, dropdowns, links, logos and layout. Rename only under an agreed convention.
5. Audit retained tabs for old brand names, dates, offers, people, links, approvals and claims. Preserve structure while replacing task-relevant residue; do not apply another brand's strategy.
6. Link the canonical documents into relevant task records. Keep client-facing and internal review versions identifiable.
7. Verify access only to the extent requested. File organisation does not authorize changing sharing or moving client data into a public place.

## Deliverable

Document register: purpose | canonical link | owner | freshness | completeness | next action. If creating files, include new IDs/locations and migration gaps.

Use the output worksheet inside the downloadable library ZIP to structure a working draft. Adapt it to the requested deliverable; do not create extra files unless useful.

## Example

A calendar master can retain the same month-tab structure while every old client offer and approval state is removed from the new brand copy.

## Verification and completion

Four core documents are covered; optional map is labelled; template readiness is checked; no old-client residue is carried forward; links resolve.

Report what was completed, the source or saved record that proves it, and any unresolved blocker. Distinguish a draft, a saved change and a live action. Publishing, posting, scheduling or changing live systems requires the corresponding user request and available tools.
