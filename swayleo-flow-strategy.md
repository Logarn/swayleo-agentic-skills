# Flow Strategy

## Purpose and provenance

Recovered from the October 23 brand-strategy rules and strategy-writing workflow.

This workflow applies across brands by substituting the current brand's sources, account, scope and approval rules. It is a reusable instruction set, not evidence that a live system is configured.

## Inputs

Brand context, flow objective, actual triggers/event properties, existing flow map, requested branch structure and approved template.

If an input is unavailable, identify its effect and continue work that does not depend on it. Do not fill factual gaps with another brand's assumptions.

## Workflow

1. Identify the lifecycle event and customer situation. Distinguish Checkout Started, cart activity, purchase and post-purchase; do not substitute one because a past flow used it.
2. Describe trigger, eligibility, profile-filter evaluation, exit/suppression, re-entry and branch rules with the platform's verified semantics. Unknown settings remain technical checks.
3. Build the main review map with these columns: Email | Job | 1. Lead (headline) | 2. Support | 3. Proof | 4. Close.
4. Give every email one job, concrete support, appropriately scoped evidence and a specific action/destination. Sequence jobs so later emails add a useful reason rather than repeat the same pitch.
5. Keep timing readable. State delay relative to the previous step and elapsed time from entry when ambiguity matters. Parallel branches are alternatives; do not add their message counts as though one person receives all branches.
6. For purchase-type paths, verify the actual checkout/event property. Subscriber status alone does not prove the checkout was a subscription purchase.
7. Retain detailed execution direction immediately above each corresponding copy section. The concise map and detailed brief must agree; preserve existing copy, claims, terms, sources and comments.
8. Use human subject-style titles and short ASCII dashes. Apply brand-specific naming only to that brand or when explicitly made a general convention.
9. Mark strategy ready for the relevant review; do not call it client-approved or release copy/design without the actual required approvals.

## Deliverable

Flow setup; six-column review map; detailed per-email briefs; copy-section mapping; technical checks; approval state.

Use the output worksheet inside the downloadable library ZIP to structure a working draft. Adapt it to the requested deliverable; do not create extra files unless useful.

## Example

Two paths of four emails mean four messages per eligible shopper, not an eight-email sequence. The last subscription-path email may offer buying once only if the strategy and destinations support it.

## Verification and completion

Trigger matches the event; branches/counts/timing are coherent; each email has one job; detailed briefs match the map; approval and technical checks remain distinct.

Report what was completed, the source or saved record that proves it, and any unresolved blocker. Distinguish a draft, a saved change and a live action. Publishing, posting, scheduling or changing live systems requires the corresponding user request and available tools.
