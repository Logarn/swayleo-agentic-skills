# Task Batch Consolidation

## Purpose and provenance

Recovered from copy/design tracker consolidation workflows.

This workflow applies across brands by substituting the current brand's sources, account, scope and approval rules. It is a reusable instruction set, not evidence that a live system is configured.

## Inputs

Exact source records, proposed grouping, titles, owners, statuses, due dates, full descriptions/copy, comments and archive authorization.

If an input is unavailable, identify its effect and continue work that does not depend on it. Do not fill factual gaps with another brand's assumptions.

## Workflow

1. Inventory original records by stable ID. Capture their current names, owners, dates, statuses, full content, links and visible comments before changing anything.
2. Define why the batch exists and its membership. Separate revision work from new production; do not collapse different states into one misleading status.
3. Create the replacement batch only when authorized. Preserve individual campaign identities and all required content with a source-to-batch mapping.
4. Verify replacement content before archiving originals. A truncated list-cell preview is not proof that full copy transferred.
5. Archive only the exact approved IDs, using a recoverable operation when requested. Preserve original statuses and dates as history rather than normalizing them to the new batch.
6. Check active replacement batches and archived originals independently. An original exposing Unarchive Item supports archive state; it does not prove every comment thread was preserved.
7. Record any content or comment-preservation checks not performed. Never delete originals merely to make the tracker look cleaner.

## Deliverable

Before/after register; original ID → batch ID mapping; copied-content verification; archive results; uncertain actions and recovery route.

Use the output worksheet inside the downloadable library ZIP to structure a working draft. Adapt it to the requested deliverable; do not create extra files unless useful.

## Example

A pre-event batch in Revision and an event batch in To-Do remain separate. Completed original records retain their historical status after archiving.

## Verification and completion

Membership exact; full content retained; replacements verified first; original history preserved; archive state read back; no unsupported preservation claim.

Report what was completed, the source or saved record that proves it, and any unresolved blocker. Distinguish a draft, a saved change and a live action. Publishing, posting, scheduling or changing live systems requires the corresponding user request and available tools.
